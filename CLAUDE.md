# CLAUDE.md

Context file for AI coding agents (Claude Code, omp, crush, …) working in this
repository. Humans will find it useful too.

## What this repo is

A personal NixOS flake managing every machine the owner runs. It is the **source of truth** for each system — the running machine is a function of these files. Multi-host by design: each machine is a directory under `hosts/`, auto-discovered by `flake.nix`.

The current host is `dev`, a Gnome Boxes / QEMU x86_64 VM running niri + Noctalia (Quickshell) — the **test bench**: every change lands here first, gets verified by a rebuild + a session check, and only then reaches real machines. Shared configuration lives in small auto-imported modules under `modules/` (one program per file); hardware-class specifics in opt-in `modules/nixos/roles/`; per-host differences in `hosts/<name>/`. A future PC or ThinkPad slots in as a new `hosts/<name>/` without touching shared files.

The repo is cloned to `~/Projects/my_projects/nixos-setup` on each machine — **there is no `/etc/nixos` symlink**; builds point at the flake path directly. Each host's `hardware-configuration.nix` (generated by `nixos-generate-config`) is **committed** under `hosts/<hostname>/` — flakes only evaluate git-tracked files, and the disk UUIDs it carries are identifiers, not secrets. To stand up a new machine, run `scripts/new-host.sh` on it; see `hosts/README.md`.

## Development workflow

The VM is the gate. A change is done when it builds, activates, and the session works on `dev` — not when it merely evaluates.

```
edit on the working machine → git add -A && git commit && git push
→ on the VM: git pull → nixos-rebuild switch --flake .#dev → verify the session
```

Consequences of this loop:
- **`git add` before building** — flakes only see git-tracked files; a brand-new module file that isn't staged is invisible to the next eval.
- The VM's repo is a plain clone (no special auth yet — `gh auth login` is on the generated `~/TODO.md`), so lock-file churn from the VM is pushed from the working machine or pulled back from it.
- CI (`.github/workflows/check.yml`) gates every PR and push to `main`: `nix flake check --no-build`, `nix fmt --check` over every `.nix` file, and a drvPath eval of every discovered host's closure. There are no tests — a NixOS config is verified by evaluating and rebuilding it. Because every host's `hardware-configuration.nix` is committed, CI evaluates with no stubbing.
- Formatting **is** enforced: nixfmt (`nix fmt`). CI fails on drift. `nix fmt` is a no-op unless you actually introduced it.

## Commands

All builds go through the flake. Substitute `<host>` for the directory name under `hosts/` (currently `dev` — `nix flake show` lists every host).

```bash
# Rebuild and switch (the default verb after any edit)
sudo nixos-rebuild switch --flake .#<host>

# Test a change without making it the default boot generation
sudo nixos-rebuild test --flake .#<host>

# Build only, don't activate
sudo nixos-rebuild build --flake .#<host>

# Bump nixpkgs / niri / noctalia / herdr
nix flake update
# Or one input at a time (Nix 2.19+ positional arg; `--update-input` is deprecated)
nix flake update noctalia

# Roll back the last activation (pair with `git revert` to keep repo + system aligned)
sudo nixos-rebuild --rollback switch

# Check the flake evaluates and outputs are well-formed
nix flake check --no-build
```

## Architecture

Modular structure — shared auto-imported module trees under `modules/`, per-machine state under `hosts/`:

- **`flake.nix`** — Inputs (nixpkgs unstable, import-tree, home-manager, nixos-hardware, niri-flake, noctalia, noctalia-greeter, oh-my-pi, herdr; lanzaboote commented out until `secure-boot.md` says otherwise) and the `nixosConfigurations` output. It does **not** hardcode a host: `mkHost` builds each machine from just its `hosts/<name>/` directory, and `builtins.readDir ./hosts` auto-discovers every host directory (adding a machine never touches `flake.nix`; `hosts/common.nix` is a file and doesn't match the filter). Inputs `follows = "nixpkgs"` to keep one nixpkgs in the closure, **with one deliberate exception: `niri`** — following it is currently fatal (niri-flake asks for `libdisplay-info_0_2`, removed from nixpkgs); the long comment on that input is the rationale record.
- **`hosts/common.nix`** — Shared wiring every host imports: `modules/core/settings.nix` (the `systemSettings` option layer), the auto-imported `modules/nixos/core` tree (`inputs.import-tree`), the niri / noctalia-greeter / home-manager NixOS modules, and the home-manager scaffolding (`sharedModules = import-tree modules/home`, `extraSpecialArgs` carrying `inputs` + `systemSettings`).
- **`modules/core/settings.nix`** — `options.systemSettings` (username, git identity, terminal) with defaults; a host overrides any of them with a plain value. Consumed by NixOS modules via `config.systemSettings` and by every HM module via the `systemSettings` module argument.
- **`modules/nixos/core/`** — Shared system modules, one feature per file (nix, boot, user, locale, network, audio, docker, nix-ld, niri, greeter, portals, shells, fonts, apps). **Auto-imported** on every host: a new file here is a new feature, no import-list edit. Paths containing `/_` are ignored by import-tree (the opt-out convention).
- **`modules/nixos/roles/`** — Hardware-class modules (`laptop.nix`: lid/hibernate/power daemons; `desktop.nix`: fwupd/fstrim), **not** auto-imported; a host lists the role it wants in its `imports`. The dev VM uses neither.
- **`modules/home/`** — Shared home-manager modules, one program per file, grouped into `shells/ terminal/ cli/ dev/ desktop/ system/ agents/ apps/`. **Auto-imported** for the user via home-manager `sharedModules`. A program's package, config, and its `home.activation` hooks live together in one file (e.g. `cli/starship.nix` owns `programs.starship` + the writable-config seed).
- **`modules/packages/` / `modules/data/` / `assets/`** — custom derivations (qq), static texts consumed by modules (starship base toml, Typora theme css), and binary assets (wallpapers) respectively.
- **`hosts/<hostname>/`** — Everything machine-specific. `default.nix` imports `../common.nix` + `./hardware-configuration.nix`, sets `networking.hostName`, role imports, bootloader/system overrides (the dev VM forces GRUB/BIOS + the MESA virgl override + SSH-by-key), and attaches `./home.nix` via `home-manager.users.<username>.imports`. `home.nix` carries per-host user overrides (VM: spice-vdagent session agent, `Virtual-1` output mode). `hardware-configuration.nix` (committed) encodes filesystems and UUIDs. The only host today is `hosts/dev/`.

### Host boot & disk

Shared default (`modules/nixos/core/boot.nix`): **UEFI + systemd-boot**. The dev VM overrides to **Legacy BIOS + GRUB** (its disk has no ESP — a single btrfs partition from the Calamares "Erase disk" install) in `hosts/dev/default.nix`; a UEFI host needs no bootloader overrides at all. Disk encryption and hibernation swap are per-host: unlock blocks live in the host's `default.nix` (per-disk LUKS UUIDs); `scripts/new-host.sh` auto-detects the swap LUKS UUID when it can. The Calamares-teardown lines in `modules/nixos/core/niri.nix` (`services.xserver.enable = false`, gdm/gnome off) are harmless on any path — they disable things that were never installed.

### niri + Noctalia wiring

Noctalia is on the **v5** line (`flake.nix` pins the `v5.0.0-beta2` tag). v5 renamed the HM module to `programs.noctalia`, replaced the v4 IPC surface with `noctalia msg <command…>`, and moved config to a declarative `config.toml`. Assume any v4-shaped snippet is stale.

System side enables `programs.niri` + `programs.noctalia-greeter` (its NixOS module sets `services.greetd` with `mkDefault`). User side (`modules/home/desktop/noctalia.nix`) imports `inputs.noctalia.homeModules.default` (with home-manager's own `programs/noctalia.nix` dropped via `disabledModules` to avoid the double declaration) and enables `programs.noctalia` with `systemd.enable = true` — the shell runs as a **systemd user unit** tied to `wayland.systemd.target`, *not* a niri `spawn-at-startup`, so `nixos-rebuild switch` restarts it cleanly instead of leaving duplicate bars. The polkit agent is Noctalia's native one; niri-flake's `polkit-kde-agent` is force-disabled in `modules/nixos/core/niri.nix` so the two don't race on the bus name.

The lock screen is Noctalia's own (`WlSessionLock`). **Noctalia does not subscribe to logind's `Lock` signal** — `loginctl lock-session` is a no-op; locking must go through `noctalia msg session lock` (the `Super+Alt+L` bind and swayidle's `before-sleep` use exactly that). Media/brightness binds in `modules/home/desktop/niri.nix` go through `wpctl`, `playerctl`, `brightnessctl` (shell-agnostic).

Idle is driven by Noctalia's own idle manager (`idle.behavior.lock`, 10 min) in `modules/home/desktop/noctalia.nix`. **swayidle** (`modules/home/desktop/swayidle.nix`) exists for one job: its `before-sleep` hook locks ahead of a sleep Noctalia didn't initiate (a lid close on laptop hosts), resolving the binary by absolute store path because the unit's PATH is minimal. `HibernateDelaySec` (3 h) lives in `modules/nixos/roles/laptop.nix` — laptop hosts only; the VM never hibernates.

### Power

`power-profiles-daemon` (not TLP — it misbehaves on Ryzen 7040 platforms) lives in `modules/nixos/roles/laptop.nix`, opt-in via the host's imports; `tlp` is explicitly disabled there.

## Editing patterns

- **Adding a system-wide package**: append to `environment.systemPackages` in `modules/nixos/core/apps.nix`.
- **Adding a user program**: new file `modules/home/<category>/<tool>.nix` with its `home.packages` / `programs.*` (and any activation hooks). Auto-imported — no list to edit; `git add` it before building. Prefer this over system packages unless the tool must be on PATH for other users or services.
- **Adding a shared system feature**: new file in `modules/nixos/core/`. Opt-out on one host: `lib.mkForce false` in that host's `default.nix`.
- **Per-host overrides (system)**: `hosts/<name>/default.nix` — plain value beats the shared default; `systemSettings.*` for the knob-style settings (username, terminal, git identity).
- **Per-host overrides (user)**: `hosts/<name>/home.nix` — e.g. `programs.noctalia.settings.shell.bar.position`, niri output modes/scales.
- **Adding an imperative install step** (not in nixpkgs): `home.activation.<name>` in the program's own file, following `apps/cyberchef.nix` / `dev/neovim.nix` — guard with an existence check so reruns are idempotent.
- **Custom package**: derivation in `modules/packages/`, referenced via `pkgs.callPackage` from the program's home file.
- **Bumping niri / Noctalia independently of nixpkgs**: `nix flake update niri` (or `noctalia`).
- **Adding a new host**: run `scripts/new-host.sh` on the target machine. It scaffolds `hosts/<name>/` (default.nix + home.nix + hardware-configuration.nix, git-added); the flake auto-discovers it. The template leaves the `nixos-hardware` module and the role import as TODOs — pick them per machine.
- **`allowUnfree` is on** (`nixpkgs.config.allowUnfree = true` in `modules/nixos/core/nix.nix`) — currently for `google-chrome`, `typora`. Unfree additions are fine.

## Secure Boot

Lanzaboote is a deliberate **post-install** step. The `lanzaboote` input (in `flake.nix`), its module line (in `hosts/common.nix`), and the `boot.lanzaboote` block (in `modules/nixos/core/boot.nix`) are all commented out — enabling them before keys are enrolled in firmware will brick the boot. The runbook is `secure-boot.md`; touch those blocks only when following it.

## What's *not* declarative (by design)

Credentials, account state, and firmware: authenticating Claude Code / Gemini CLI / `gh auth login`, signing into browser sessions, joining Tailscale, picking the wallpaper in Noctalia, `sudo fwupdmgr update`. These are account credentials, physical actions, and firmware — not something Nix should own.
